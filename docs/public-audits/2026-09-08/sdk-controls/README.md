# Provider SDKs and live controls

Checked September 8, 2026. T3 main is pinned at `5e6cc2b89534a8e01772bf647b79a1f2da2f9664`; its orchestrator V2 branch is pinned at `6102d00bdb06f4318be3fad2c79465c08186f45e` (PR 2829). These are distinct implementations. This report does not claim Mako is better overall or that V2 parity has been established.

## What T3 actually uses

T3 controls provider processes through structured APIs. Starting a subprocess does not mean typing into a terminal or parsing its screen.

| Provider | T3 main | T3 V2 finding | Mako after this change |
| --- | --- | --- | --- |
| Claude Code | Anthropic Agent SDK `query` | Agent SDK; priority `now` for steering | Agent SDK 0.3.263; typed options, input, permissions and events |
| Codex | Codex app-server | App-server; steering includes `expectedTurnId` | App-server; generated request types and exact-turn steering; manual compaction withheld |
| Cursor | `agent acp` | Cursor SDK create/resume; adapter explicitly rejects steering; `/compress` for compaction | ACP retained; no claim of active-turn steering |
| Grok | ACP | Not re-audited in this pass | Existing provider-owned ACP transport |
| OpenCode | `@opencode-ai/sdk/v2` | Not re-audited in this pass | Existing provider-owned ACP transport |
| Antigravity | ACP | Not re-audited in this pass | Not a Mako provider |
| Devin | Not among the inspected built-in T3 drivers | Not established | Existing provider-owned transport |

OpenAI recommends [app-server](https://learn.chatgpt.com/docs/app-server) for rich clients needing authentication, history, approvals and streaming. Replacing it with the simpler TypeScript SDK would not automatically improve Mako. Its request types are now generated by `npm run generate:codex-inputs` from the installed Codex CLI instead of duplicating request shapes by hand.

The current [Cursor SDK](https://cursor.com/docs/sdk/typescript) documents steering for supported local runs, with explicit outcomes and fallback behavior. That is newer capability than the inspected V2 adapter uses. Migrating Mako needs proof that interactive approvals, local authentication and existing native session history survive; this change does not trade those features away to advertise an SDK.

## Implemented behavior

- Claude's ACP adapter dependency and registration were removed. Its provider module registers a direct Agent SDK driver. The SDK's bundled CLI is the default; an explicitly configured `CLAUDE_CODE_EXECUTABLE` is honored. User, project and local settings and account environment remain provider-owned.
- SDK permissions map into the existing approval and question UI. Session permission grants include only SDK suggestions with a session destination. Dismissal denies the request. Streamed and complete messages share transcript identity; tool images retain their owning result.
- Claude exposes optional `steer` and `compact` capabilities; Codex exposes `steer`. The shared host does not branch on provider names. Enter queues a prompt; Cmd/Ctrl+Enter steers a supported running turn. The composer exposes Steer while working and Compact while idle.
- A steering action names the exact active request and native run. The host saves its intent before dispatch. Repeated action IDs return the saved receipt; a changed payload with the same ID is rejected. Restart converts interrupted dispatches into uncertain receipts and never replays them.
- Claude confirms steering through echoed client UUIDs on user, stream or result events. A message folded between tool rounds can be acknowledged only in the final result. The default acknowledgement window is two minutes; timeout remains uncertain, never evidence of non-delivery.
- Compaction remains pending until the provider emits an actual terminal event. A JSON-RPC acceptance alone is insufficient. Queued prompts wait behind pending control receipts. An uncertain action is visible in the conversation; compaction recovery disconnects the provider before allowing new work.
- Clean disconnect awaits provider process exit before refreshing the native fingerprint, because Claude writes metadata during shutdown. This is covered by an integration regression. The bundled native CLI is unpacked for Electron packaging; native process startup uses the unpacked executable path.
- Claude Stop closes the process after interrupt, including when interrupt times out, so queued SDK input cannot silently execute afterward. A later continuation uses native resume only when the existing unchanged-file and inactive-process checks permit it; otherwise the established portable handoff applies.
- Steering text and retained attachments are part of the portable transcript. Steering does not reset the current turn's tool/result reconciliation or create a false workspace rewind boundary.

## Reproducible checks

Run `npm run test:live-actions` for the durable host receipt tests and typed SDK driver tests. They exercise duplicate requests, stale active turns, storage failure before dispatch, uncertain restart, queue ordering, compaction completion, SDK delivery timeout, Stop timeout, close during initialization, questions, denied permissions, streaming identity and tool image ownership.

Opt-in real provider checks:

```sh
npm run build:electron
MAKO_REWIND_PROVIDER=claude node scripts/test-rewind-e2e.mjs --controls --compact
MAKO_REWIND_PROVIDER=codex node scripts/test-rewind-e2e.mjs --controls
```

These create disposable Git workspaces and isolated Mako application data. They spend real provider tokens, write only the fixture file through narrowly checked approvals, verify that a model received a random steering marker, optionally wait for compaction completion, verify native resume and recall, and restore the first workspace checkpoint into an idle conversation fork.

## Limits and remaining comparison work

Codex manual compaction is deliberately not registered. The real app-server accepted it and emitted completion, but its native `compacted.replacement_history` omitted the earlier task and steering marker. After resuming the same native session, the model could not recall that marker. Only the disposable test session was affected; its complete transcript remains in Mako. A green RPC receipt is insufficient to enable a context-altering control. The protocol implementation remains available for diagnosis, but the composer and shared capability registry do not expose it.

Cursor steering is not implemented. Claude's exact native fork-at-turn capability is not advertised by the new SDK driver; portable conversation forks and workspace rewind remain available. A late acknowledgement after the two-minute steering timeout does not silently turn an uncertain receipt into a confirmed one. That receipt must be acknowledged and is never automatically resent.

Overall superiority still requires matched model/budget workflows and further checks of automatic iframe observations, browser helper coverage, native computer scripting, packaged permissions, checkpoint retention and large-repository latency. This pass changes the workspace; it does not replace the installed Mako application.

## Verification results

The enabled controls passed the real provider checks: Claude steering, compaction, native resume and recall; Codex steering, native resume and recall without compaction. Both also passed real file writes, checkpoint preview, workspace restoration and idle fork creation. See `claude-result.json`, `codex-result.json`, and the separate `codex-compaction-failure.json` finding.

The final source passed `npm run build`, `npm run test:live-actions`, `npm run test:codex-protocol`, `npm run test:providers`, `npm run test:live`, `npm run test:transcript`, and the complete `@mako/sessions` suite. MCP, web gateway/preload, workspace snapshot, and type checks also passed during this change. SDK fixtures were separately typechecked against the installed SDK declarations.

`npm run lint` passed with zero errors. Oxlint reported zero errors and warnings. ESLint retains two existing React Compiler warnings at the isolated TanStack virtualizers in `file-tree.tsx` and `search-view.tsx`; no rule was disabled. The production build retains its existing chunk-size and mixed static/dynamic import warnings.

The real Chrome UI was inspected on a live Claude conversation. The working composer showed Enter queues / Cmd+Enter steers, a Steer control and Stop; the idle composer exposed Compact. Confirmed steering appeared under its original prompt with one whole-answer copy action. The SDK projection regression additionally verifies that a final text block following thinking retains its streamed index rather than duplicating the answer. Portable fork entries retain steering ownership.

Packaging configuration now unpacks the SDK native executable and remaps its launch path outside `app.asar`. This pass did not build or install a new desktop release, so packaged execution and permissions remain a separate verification item.
